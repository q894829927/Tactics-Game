# C2-0 战前整备、战后结算与角色进度持久化

## 正式浏览器流程

1. **整备阶段**：首次进入显示独立整备面板；可以为4名角色选装备或进入C1职业整备。此时不能在战场移动/攻击/结束回合。
2. **确认出击**：4名角色的当前职业/武器合法后进入原4v6测试关卡，恢复当前出击的魔法次数并将整备队伍保存为安全检查点。物理武器耐久不修复。
3. **战斗阶段**：执行现有W0/W1/W2/P1玩法与敌方行动；中途刷新不会写入未结算的临时HP/经验/战场进度，恢复为上一次的整备快照。
4. **胜负结算**：保留胜/败原因及每名友军等级、人物经验和七系武器经验的变化，自动保存已获得的角色成长。
5. **返回整备**：重建地图、敌人和出战起点，重置临时行动/随机数，恢复友军HP；保留人物长期数据与装备耐久，进入下一次出击。
6. **主动清除**：整备面板提供二次确认的队伍重置；区别于放弃本次尚未结算的战斗。

## 持久化的数据

`CampaignSave`：`schema:1`、`sortiesCompleted`、已有`preparationFunds`、严格4人`allies`进度、可选`pendingSettlement`。每名友军保存：
- 永久个人能力`stats`、基础`growths`、`maxHp`、`level`、`exp`；
- 七系`weaponExp`、当前`classId`、独立的`classLicenses`；
- `inventory`、`equippedIndex`、每件`weaponInstances`的独立耐久、`spellCharges`、可替换训练槽位`trainingSlot`。

**不持久化**：坐标/地形状态、敌方单位、战斗内HP、回合和行动标志、移动试探状态、动画队列、随机数状态、战斗事件、战斗日志。本版没有自动关卡奖励，也不存在出售/修复资源行为。

使用`localStorage`键`wildfield-tactics.campaign.v1`，读取前校验schema、阵容ID、职业许可、武器定义、物理实例、法术剩余次数、所有经验/属性上下界；损坏、未知或不完整版本拒绝读取，避免非法角色进入战斗。数据仅存当前浏览器；换设备、清空站点数据或浏览器无本地存储权限可能失去进度，**不声称账号级云保存**。

## 战斗兼容性边界

- `new Battle()`默认保留既有原型玩法和测试行为；正式页面使用`new Battle({campaign:true,save})`明确启用新流程。
- 回到整备时可再次进入**同一测试地图**，未开发新关卡、地图路线或多关剧情。战斗重开采用出击前安全存档，不抹去过往已结算进度。
- HP在整备时自动恢复（不包含治疗消耗）；攻击魔法**在确认新出击时**补满次数，而非每回合自动补；耐久和各类职业/个人经验永久保留。
- 失败也可带着已获得的个人经验返回整备，不永久删除阵亡角色。考试券、金币、名声的来源由后续C2-1实现。
- 本阶段只提供战役内浏览器存档；不支持完整战中断点、跨浏览器同步或多存档栏位。

## 验收

引擎测试包括：整备阶段行动隔离；转职与装备持久化；刷新存档校验；安全检查点回退；胜负结算及重启后恢复；多次出击不复制装备、不清空成长；伤员HP与魔法次数时机、物理耐久延续；坏存档拒绝读取；确认重置与普通战斗重开的区别。

浏览器三种视口：整备弹窗 → 职业切换 → 关闭 → 保存及刷新 → 确认出击 → 原地图选择/移动/撤销与交互测试。战后弹窗使用引擎专项测试验证状态，后续多关开发再加入完整剧情UI验收。

## C2-1 继承更新（v0.1.29.0）

此前本文件说明的“暂无金币、名声、考试券来源”已由[C2-1战斗奖励规则](C2-1-REWARDS.md)补齐。现胜利固定获得200金、40名声与1张中级考试券，战后显示奖励并记录在同一份本机存档。C2-0的其他战前整备与角色持久化规则不变。

## C3继承扩展（v0.1.30.0）

角色存档在原有C2-0字段之外，增加`classExperience`（独立职业XP）与`equippedMasteries`（最多2个精通被动ID）；历史存档缺字段时安全空值迁移，仍保留原职业认证与装备。战后结算增加每名友军的职业经验增长。详情见[C3职业经验与精通](C3-MASTERY.md)。
