# 火焰纹章地图制作研究与 Tactics-Game 模块化美术方案

> 状态：**设计方案，待实施与截图验收**。研究日期：2026-10-13。以当前游戏 **v0.1.4.1** 为代码基线。本文仅规划，不代表瓦片编辑器、自动拼接或新资产已经集成。
>
> **明确决策：不再用一张 AI 大图充当完整地图。** 应采用“战术规则格 + 微瓦片连续地表 + 边缘自动连接 + 独立环境物件 + 屏幕 UI”的混合 2.5D 渲染。旧的 `ai/forest-cliff-river-stage.webp` 留作视觉参考和过渡回退，不作为最终地图的唯一底图。

## 1. 火焰纹章研究结论：不等于复刻官方内部引擎

### GBA 世代：组合瓦片 + 地形规则

- `FEBuilderGBA`、`Tiled` 的火纹改图流程使用 **16×16 像素瓦片**，地形与美术可以分别指定。森林、河道、路口、城墙不是每次画一张完整关卡截图。
- 社区的火纹地图编辑器会记录瓦片的相邻关系，用于检查相邻拼图是否合理，并允许自动生成后手工修补。
- 对本项目的价值：**固定的棋盘格坐标；地表、边缘/转角、树、岩壁、桥、装饰分离；每格地形类型独立影响移动与防御**。

### 3DS / Switch 世代：丰富视觉 + 仍需可读战术格

- 《火焰纹章 觉醒》开发者在访谈中讨论 2D 单位标记置于 3D 地形的遮挡顺序，避免建筑遮挡人物；也明确讲到**先在方格纸上设计地图，做无美术的玩法测试，再持续调整**。
- 《风花雪月》官方介绍地形对战斗的影响，也支持缩放/旋转地图视角；《Engage》有独立的范围高亮、单位表现和复杂地形环境。
- 公开资料无法还原现代火纹的私有内部 3D 地图工程结构。我们仅借鉴**玩法优先、环境立体、格线/行动高亮独立、单位绝对可读**的原则。

## 2. 现有工程约束（必须保持）

| 参数 | 现状 / 采用值 | 新系统操作 |
|---|---|---|
| 战术格 | 10×8，92×92 世界单位/格 | 不变。仍以 `Battle` 地形和单位坐标为权威 |
| 完整场景 | 16×12 等效战术格，1472×1104 | 不变。外围属于装饰，不允许战斗点击 |
| 战术原点 | (276,184) | 不变。对应完整场景中的列 3、行 2 |
| 地形类型 | `.` 平地、`F` 森林、`H` 丘陵、`#` 峭壁 | 不变。水和木桥先仅放在不可游玩的场景外 |
| 镜头 | 0.60–1.85 | 不变，所有世界图层共享相机参数 |
| 文字与 UI | DOM/S70/S80 | 不随世界缩放 |
| 地形贴图粒度 | **建议新增 46×46 世界单位微瓦片** | 每 1 战术格 = 2×2 微瓦片；32×24 = 768 个地表小瓦片 |
| 导出像素 | 2× 最低 92×92 px/微瓦片 | 不要求 AI 直接生成这个尺寸；应从高分辨率母版整理、修接缝后导出 |

46 世界单位是**建议的新视觉微瓦片粒度**，不改变冻结的 92 世界单位战术坐标，不增加 768 个可互动格。正式做前先试验同一拼接单元在 60%、100%、185% 缩放下是否清晰。若 46 太细，可退回 92 地表格 + 独立过渡贴片，无需更改玩法数据。

## 3. 五类素材：各自有不同的制作和铺装方式

| 资产层 | 资源类型 | 使用方式 | 当前推荐的完整套装目标量 |
|---|---|---|---|
| G1 地面 | 草地、暗草、泥土、土路、碎石、平坦岩顶 | 46 单位微瓦片，至少 3 种基础地表 × 3–4 变体 | 12–18 |
| G2 地形过渡 | 草↔土、草↔石、土↔石的直边、外角、内角 | 邻接掩码自动拼接，不使用硬方形遮罩 | 24–40（首批只做一组） |
| G3 水系与地势 | 河面、岸线、泡沫、河道弯角、崖顶、崖面、台阶 | 水面重复瓦片 + 不规则岸线覆盖 + 分段崖壁 | 16–24 |
| O 物件精灵 | 针叶林 3–5、树簇、灌木、石块、倒木、木桥、旗帜、营寨件等 | 带透明通道的独立图片，世界坐标锚点与遮挡规则 | 18–30 |
| FX 细节 | 草丛、野花、碎石、落叶、树影、低雾、水雾、火光 | 半透明贴花/轻量粒子，使用确定性分布 | 6–12 |

以上是**全场景资源库目标，不是单次必须生成 100 张图片**。优先落地可复用的组合模板。每个独立资源都需要注明：源图、制作方式、导出文件、宽高、锚点、遮挡层、许可/来源、验收状态；明确区分 `generated`、`processed`、`integrated`、`visual_approved`。

### 这次已经生成的独立素材应该怎么使用

本次对话里已生成森林草地、碎石道路、河面、森林簇、悬崖、河岸和木桥等候选素材，但**还未审定能否无缝拼接，未验证每张图的 Alpha 通道和投影一致性，也未据此重写地图**。

- 草地/道路/河水：仅视为**高分辨率母版**。不能直接将 1254×1254 全图缩成每个小格；需裁选、去除显眼中央构图、修四条边使相邻纹理连贯，再制作多变体。
- 森林簇/石壁/河岸/木桥：优先处理成**透明独立贴图**，保存真实 Alpha 通道，裁去过量透明边距，并给出实际落地点。不能仅因预览背景看上去黑色就假设透明正确。
- 石壁/河岸：一张大物件不等于可连接的连续悬崖。需补直段、内角、外角、终点/缺口，配合地形邻接规则。
- 禁止把这些官方火纹截图或过去的 AI 全场景图片裁成纹理来复用。火纹图片仅作研究，使用原创 AI / 人工修图资产。

## 4. 自动拼接技术：解决现在一格格像贴纸的问题

1. **基础地面**：铺草地/土路/碎石微瓦片。同种地面用固定随机种子选择变体，避免重复花纹和游戏刷新时跳变。
2. **Terrain Set 过渡**：检测相邻瓦片的材质类型，用 4 邻/8 邻掩码选对应直边、内角、外角。Tiled 的 Edge/Corner Sets 可用 16 种完整二地形配置起步；后续复杂地形可以采用精简 47-tile Blob（并非简单的所有 47 张可随意转向）。
3. **河道**：水面按段铺装；岸线由水陆邻接掩码决定方向，浅水、泡沫在不同贴花层叠加，不能把岸、水、树画进同一重复贴图。
4. **悬崖**：独立顶面与立面，立面按岩顶边界延伸，凹凸拐角使用专用素材。可参考 Tiled 文档“RPG Cliffs”自动映射示例。
5. **环境物件**：位置来自独立场景数据（不改变逻辑地形）；植被随机重复要遵守避让区域、交战通道和单位可读性，不得盖住 UI/攻击目标。
6. **高低层处理**：世界坐标依据锚点，物件按脚点 Y 参与绘制排序；单位若被树冠遮挡，降低部分树冠不透明度或显示单位清晰轮廓。

**禁止在含方向光和投影的地表上随意旋转/垂直镜像贴图**，这会造成光照方向跳变。水平镜像同样须审核视觉，贴图本身的明暗不一定对称。

## 5. 逻辑数据与场景数据彻底分开

建议最终在 `src/maps/` 添加关卡地图数据模块，示意：

```ts
type TerrainCode = "." | "F" | "H" | "#";
type Prop = {
  assetId: string;
  worldX: number;
  worldY: number;
  scale: number;
  anchorX: number;
  anchorY: number;
  occlusion: "ground" | "behind-units" | "front";
};
type StageArt = {
  worldSize: { width: 1472; height: 1104 };
  tacticalOrigin: { x: 276; y: 184 };
  logicGrid: TerrainCode[][];     // 10x8, maps to Battle
  groundVisuals: string[][];     // 32x24, only art
  sceneryProps: Prop[];         // world objects
  visualSeed: number;           // deterministic variants
};
```

`logicGrid` 不应成为第二份无同步的战斗权威；可以引用 `Battle` 的现有地形，在美术侧保存与其一致的源数据。所有会让玩家误解通行属性的物件应拒绝通过校验：比如把水/不可行桥放在逻辑平地上，或把可通行平地画成悬崖。

## 6. 渲染分层与技术路线

继续保留已实施的 `world-stage`、W40 战术命中、W45 高亮、W50 单位、S70 标签和 S80 HUD。

建议将静态美术改为以下分组，避免每个地表变体都创建过多 DOM：

```text
world-stage / camera transform
  G1   ground-tile-canvas      32x24 小瓦片底层
  G2   transition-canvas       地形过渡 / 贴花
  G3   terrain-water-canvas    河面 / 河岸 / 岩壁基座
  O1   behind-unit-props       树根、树冠背面、地形建筑
  W40  tactical-hit-grid       仍为 10x8 DOM 输入区
  W45  tactical-highlight      DOM / Canvas 范围显示
  W50  world-units             单位标记与脚点
  O2   foreground-occlusion    树冠、桥栏杆/受控遮挡
  S70  screen-unit-labels      文字、HP 与操作菜单
  S80  screen-HUD              小地图和状态栏
```

初期用 **Canvas 2D + 资源图集 + DOM 交互**，不急于为了“像现代火纹”引入 Three.js/全 3D 引擎；性能瓶颈出现后再评估 PixiJS/WebGL。缓存静态地面，移动镜头只做共同变换，更新动态单位/高亮不重绘整个场景。小地图基于相同地面/景物数据离线或缓存生成缩略图，再叠加即时单位点与镜头框，避免两套地图不一致。

## 7. 分期资源量与具体交付

### M1：重制首块森林—石壁—河岸样片（下一步，只做这块）

目标位置：右侧河岸附近约 6×5 个等效世界格（约 552×460 世界单位），包含林地、可行走草土坡、真实岩壁和不可游玩的河岸。**先做这个自然过渡，再铺整关**。

第一批建议 **26 项生产资源**：

| 内容 | 数量 | 验收 |
|---|---:|---|
| 草地/土径/碎石基础瓦片及变体 | 6 | 3×3 铺设没有明显方块边界 |
| 草↔土 / 土↔石过渡片 | 8 | 四个方向、转角能自然相接 |
| 水面与岸线 | 4 | 河水流向与岩岸没有硬直线 |
| 岩壁顶面、立面、转角、石堆 | 4 | 高低差和不可行区域可判断 |
| 森林树簇/单树/灌木 | 3 | 统一光照与正确落脚点 |
| 碎石/野花/阴影细节 | 1 组 | 在地面局部覆盖，不能挡人物 |
| **合计** | **26** | 上述为候选资源及其派生片总数量，不要求生成 26 张独立 AI 原图 |

任务 M1-1：统一绘画透视、比例、光线和色板；从 AI 原图中筛选合格源资产。  
任务 M1-2：制作/修补微瓦片与地面过渡资源，并将纹理划入图集。  
任务 M1-3：用实际 Alpha 精灵拼出树丛、悬崖与河岸，依据坐标而非固定截图显示。  
任务 M1-4：完成 552×460 局部场景与小地图同源显示，在 60%/100%/185% 下截图验收。

**M1 完成条件**：可以移动/替换树、改变河岸布局而不重画整图；没有明显的 92px 方形缝隙；每条岩壁与岸线连续；森林与单位遮挡正确；在手机和桌面上角色清楚可点击；战斗逻辑测试不变。

### M2：扩展整个 16×12 舞台

- 把可复用过渡规则和已审定的材质铺满；补左上密林、左下入口、中央交战道路和右侧石桥。
- 追加河道拐弯/桥端、崖壁长度与阴影、树型变体、石阶/营地赤旗、木栅栏/帐篷等。
- 保证 10×8 行动层与所有外部装饰的可达性一致；新关卡复用资源库但拥有不同场景数据，不再靠生成整张大图。

### M3：关卡制作器与批量验收

- 先选用 Tiled TMJ 格式或自定义 JSON 编辑器之一，不同时写两套编辑工具；Tiled 更适合现阶段人工绘制瓦片与物件。
- 建立地形笔刷（自动补相邻过渡）、物件图层、遮挡预览、场景边界标记及资源缺失提示。
- 对第一关生成完整的地图缩略、碰撞图、地形规则覆盖图和装饰预览。
- 连续新建第二张**不同布局**的样例地图，验证素材不是第一关专用贴图。

## 8. 质量门槛、性能、版本与停止条件

**视觉 P0 检查（全部满足）**：

- 参考图所要求的密集林冠、真实岩壁、水岸/桥自然接续，且没有拼贴接缝和重复感特别强的“纹理印章”。
- 原创画面统一高角度俯视投影与左上主光方向，不随贴图翻转造成阴影错乱。
- 单位不被树林遮住；走与不能走的地形具有明确视觉边界；点击战术格依旧准确。
- 在 **1920×1080、1366×768 和窄屏手机**检查；60/100/185% 缩放截图记录，含拖动、单位移动和攻击之后的状态。
- 第一关冷启动目标：首屏地形资源压缩下载尽量 ≤6 MiB、全部场景地形资源尽量 ≤10 MiB（目标非现有测量）；首屏可先呈现低分辨率/占位地表。

**明确停止条件**：如果只有一张精美 AI 图，但无法更换其中的树、岩壁、河道或覆盖衔接不自然，不能标记“模块化美术完成”；如果无法保证地形与规则一致，停止铺设并先修相应基础数据/遮挡规则。

**版本约束**：本次保存文档仅是修订，升级第四段。完成 M1 等真正可交互新功能后，再根据 [VERSIONING.md](VERSIONING.md) 升级第三段，每次把具体变化写进 CHANGELOG。未完成/未验收的 M2、M3 不提前占版本号。

## 9. 决策总结

- 不再将 `ai/forest-cliff-river-stage.webp` 当作最终地图。
- 不把整张图片粗暴裁成若干小格后称作“可拼地图”，因为这样无法重构河流或森林。
- **最短可落地路线**：26 项派生微瓦片和独立精灵 → 6×5 小场景 → 自动过渡 → 完整关卡。
- **关键验收指标不再是素材文件数，而是同一批素材能否在两张不同布局的地图中自然复用。**
