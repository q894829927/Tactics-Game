# E1-0：战前武器维修与金币经济闭环

## 范围

原有C4-1C能够给战役发金币，C4-1D验证了不刷关通关。E1-0是第一笔真实可选经济支出：修复因使用战技而损耗的物理武器耐久。

- 入口：正式战役的「战前整备 → 选择角色 → 随身装备 → 装备维修」，原生折叠面板，手机也可上下滑动。
- 可以按单件修理，也可「一键修理全队」。只消耗金币，无名声或凭证支出。
- 只恢复已经损耗的物理耐久；普通攻击不消耗耐久，战技可能消耗。魔法次数维持每次出击自动恢复。
- 没有金币时仅禁止购买，仍可以出击，不会发生战役软锁。
- 战斗、测试地图、结算界面均不开放维修；成功后触发一次保存。刷新后耐久与金币仍正确；放弃一次战斗不会返还曾经花掉的金币。
- 本阶段不包含武器购买、武器替换、修理材料、商店或随机售价。

## 价格与经济规模

| 武器熟练要求 | 每恢复1点耐久 |
|---|---:|
| E | 2金币 |
| D | 3金币 |
| C | 4金币 |

举例：铁剑(E)耐久14/24 → 需要恢复10点 → 20金币；钢剑(C)耐久10/20 → 40金币。

C4-1C的四关首次通关奖励合计1220金币、6张中级券。职业中级考试每次150金币/1券，因此需要避免一次修理耗尽预算；这里选择较小的按需修理价格。当前不改变关卡奖励，后续根据真实各职业战技使用量决定是否调价。

## 实现与验收

- src/engine/campRepair.ts：纯报价算法，不产生扣费副作用。
- Battle.repairQuote、partyRepairQuote、prepareRepairWeapon、prepareRepairAll：正式阶段检查、完整余额核算、单件/整队执行与唯一通知。
- tests/e10CampRepair.test.mjs：报价、低金币、重复消费、非战前拒绝、全队原子操作、保存/重读、魔法不维修、测试模式隔离。
- tests/browserE10Repair.mjs：桌面/手机实际操作：合法测试存档、显示维修与费用、支付后验证金币/耐久、刷新不回退，再确认出击。
- 游戏存档结构仍为schema=1，不需迁移字段。
