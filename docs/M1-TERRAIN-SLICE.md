# P0 M1：森林—岩壁—河岸 6×5 竖切片

> 版本 `v0.1.20.0`。**代码与自动化回归完成；最终美术主观评审、真实浏览器截图还未通过**。不把可渲染等同于最终画质验收。

## 实施范围

- 冻结世界舞台 16×12 格、单格 92，战术命中区为世界列 3–12、行 2–9 的 10×8 区域。
- 局部 M1 样片为 **世界列 10–15、世界行 4–8**，共 6×5（552×460 世界单位）。覆盖东侧可玩地表、树林/岩石组合和不可点击的河岸。
- `src/scene/terrainTransitions.ts` 给出全图 32×24、46 单位的视觉微瓦片、草土四向邻接位掩码（N/E/S/W=1/2/4/8）和局部样片快照。逻辑仍读取 `Battle.terrain`。
- `GroundPainter` 用原本的 384 单位羽化底图加一层 46 单位、四边羽化的地表细节纹理，固定坐标种子保证关卡刷新、镜头移动和攻击时画面不跳动。
- `mapScenery` 在右岸沿线复用已有 WebP 透明石块和针叶树；同时深化岸边水纹、湿地边和石屑。原地形 F/# 上的物件覆盖规则不变。
- **M2 全关扩展**不是另写 16×12 背景图：微瓦片与海岸物件的同一过程直接覆盖整个第一关；小地图读取同一地表 Canvas 与景物列表。

## 自动化交互安全门槛

1. 768 个微瓦片均与逻辑地形分类一致，且固定输入返回稳定种子。
2. 6×5 子区域含土草边界、河岸，局部样片能独立标定；河水、岸边物件不触及战术区。
3. 10×8 命中格、地形加权寻路、攻击与反击不因美术改变；美术图层 `pointer-events:none`。
4. 缩略图必须同源；摄像机 0.60/1.00/1.85 的可逆坐标与手机拖拽由既有自动化测试验证。
5. 素材加载失败可退回程序着色，不影响战斗。没有变更任何玩家游戏规则及 ECS 的 `main→site` 验证路径。
