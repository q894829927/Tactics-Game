# 战斗预测布局 V3（v0.1.44.0）

目标：对照火焰纹章万紫千红的**空间关系与信息层级**，而非复制其知识产权素材。

## 四层关键数据（不改引擎）
1. 当前 HP：两侧血量原值围绕中央 HP 菱形展示。
2. 命中/必杀：同一横排，各自阵营半区排版。
3. 首击伤害、仅在发生时追加追击：伤害显示在承受方一侧，不存在时隐藏。
4. 剩余 HP：蓝/红细长血条及靠近中心的大号剩余值。

## 美术和分层
- 项目自绘六套职业原型半身 SVG，仅表达武器/职业视觉风格，不代表已经有独立角色立绘。
- 角色位于底层，姓名职业武器信息叠在上方，地图在预测区上沿仍可见。
- 窄条操作按钮、金色横向细线、轻量渐变暗幕、金属血条外框/刻度/预测指针。
- 响应式调整：手机缩小人物与姓名条，保留至少40px高的确认按钮，预测区避让手机快捷栏。

## 主要文件
- `public/assets/ui/portraits/*.svg` 六张独立原创肖像
- `src/scene/forecastPortrait.ts` 纯职业/阵营→肖像映射
- `src/scene/BoardView.ts` 保持原预测模型与业务流程，只负责实时更新肖像地址与fallback
- `index.html`, `src/style.css` 新视觉层与移动端样式
- `tests/forecastVisual.test.mjs`, `tests/browserForecastVisual.mjs` 职业映射、DOM层级、资源加载、尺寸/遮挡/按钮及截图

旧版结构性 CSS 和原始预测函数继续存在，避免破坏已有菜单/治疗/敌方回合/战斗预测测试。日后补齐独立角色立绘时，仅需更换映射源和 SVG/图片素材。


## v0.1.45.0 — 逐次出手预测

- 移除将命中/必杀直接绑定到左右角色的固定一行，改为按出手序列生成行，每行独立显示【必杀】【命中】并在对侧展示该击的伤害。
- 出手顺序：先攻方首击 → 合法反击（如有）→ 追击（如有）；敌方先攻时行的左右关系随实际出手者反转。
- 首击的战技/职业/被动命中加成不复制到追击。追击专用 followUpHit、followUpCrit 在 forecastAttack() 单独计算；预测仍按普通命中、无必杀的假设计算最终 HP。
- 无法反击/无追击不生成行，没有伤害不显示伤害数字；无需额外「命中保底」「魔法伤害」「耐久」说明。
- 由于攻击能否命中、必杀以及伤害引发的状态变化属于实战分支，实际结果仍可能与这种确定性的普通命中预览不同。


## v0.1.45.1 — 固定表头，逐击数字对齐

左侧概率区域为两列固定表头「必杀　命中」，右侧镜像为「命中　必杀」。只在顶部写一次列名，逐次出手只放数值，例如：

| 必杀 | 命中 |
|---:|---:|
| 30 | 99% |
| 50 | 100% |

首击与追击分别读取引擎独立预测数据，反击显示在对侧同样两列；没有出手的一方没有多余标题。每一列的 CSS 宽度、间隔在表头和所有出手行共享同一组尺寸变量，移动端亦如此。

## v0.1.45.3 — 命中/必杀与伤害分行

- 一次出手占两层：上层显示对应攻击者的「必杀、命中」概率，下层在受击者半区单独显示该击的伤害；不再让 `89%` 和 `−6` 出现在同一横行。
- 首击、反击、追击按原出手顺序排列；每一击上下两层保持关联，表头仍只显示一次，左右双方的概率列宽与表头一致。
- 使用响应式双层网格；不影响不带出手者标记的治疗/辅助行，也不改变引擎预测、结算和 HP。

## v0.1.45.4 — 逐次攻击「必杀　命中　伤害」同一行

- 使用指定样式：仅保留「必杀　命中」两列标题，单次出手的数值在同一行连续显示，例如「30　100%　40」，第三个无标题数值为该次攻击造成的伤害。
- 我方出手依次为「必杀｜命中｜伤害」，敌方出手在右侧镜像为「伤害｜命中｜必杀」；不再把伤害单独放到下一行或另一角色半区。
- 各击固定列宽并对齐表头，涵盖首击/反击/追击及桌面/手机；实际伤害、命中、必杀、血量及结算不变。

## v0.1.45.5 — 修正伤害符号及受击方归属

- 命中与必杀属于本次出手者，伤害值属于受击者；每击仍在同一横行，但出手方显示两列概率、另一侧显示 `−6` 形式的伤害。
- 我方出手伤害显示在右侧敌方半区，敌方出手伤害显示在左侧我方半区。上一版同侧第三列的样式被撤销。
- 治疗只在受治疗者一侧显示 `+6` 等正增量；零伤害时无伤害数值；反击和追击按各自出手方向分别显示。
