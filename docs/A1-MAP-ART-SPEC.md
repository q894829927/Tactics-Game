# A1｜赤旗要塞地图美术规格与场景布局方案

**状态：A1 方案初稿已形成，待评审。** 尚未生成或采购素材、尚未实施 A2 渲染重构。目标依据：用户确认的暗黑奇幻森林、河流、石崖、木桥与赤旗敌营 UI 示意图。

关联文档：[四阶段实施计划](VISUAL-IMPLEMENTATION-PLAN.md)、[战斗规则](GAME-DESIGN.md)、[UI 参考规范](UI-REFERENCE.md)。

## 一、边界和总体设计

- 战斗逻辑维持目前的 **10×8 网格，4 名友军对 6 名敌军**；不变更寻路、行动力、伤害、防御与出生位置。
- 通过可玩区四周的 **不可交互装饰景观** 扩张舞台，让森林、山崖、河流、桥和营寨共同构成完整战场，不再出现孤立的 10×8 色块。
- 选择 **高角度俯视的 2.5D 正交方格风格**：人物和树木有体积感、崖壁有高度差，但屏幕上的战术格依旧是水平/垂直排列。暂不改成 45° 菱形等距网格。
- **不可将整张带人物/UI 的目标示意图作为游戏底图。** 地表、树木、河水、桥梁和营寨须可独立分层、裁切、替换；DOM 文字及交互格继续保留。
- 当前引擎没有水域/桥梁规则，所以 **河与桥必须在可玩区之外作为装饰**。以后想跨桥作战必须单独改地形规则、寻路与测试，不能仅靠贴图假装可以通行。

## 二、坐标与画布规格（A2 实施目标，不是当前实现）

已核实：MAP_WIDTH=10、MAP_HEIGHT=8；当前单格 TILE=92 CSS px；原始战术网格为 **920×736 CSS px**，左上角逻辑坐标 (0,0)，x 向右，y 向下。

| 数据项 | A1 推荐方案 |
| --- | --- |
| 战术逻辑区域 | 10×8 格，920×736 CSS px |
| 场景装饰边距 | 左 3 格、上 2 格、右 3 格、下 2 格 |
| 建议扩展舞台 | 16×12 等效格，**1472×1104 CSS px** |
| 战术区起点（在新世界舞台中） | **(276,184)** CSS px |
| 战术区范围 | x 276 到 1196（不含），y 184 到 920（不含） |
| 镜头缩放 | 保留已有的 60%—185% |
| 首次浏览器验收 | 1920×1080、1366×768，含 60%、100%、185% 缩放 |

~~~text
逻辑格左上角世界位置
  worldX = 276 + 92 * x
  worldY = 184 + 92 * y

逻辑格中心世界位置
  worldX = 276 + 92 * (x + 0.5)
  worldY = 184 + 92 * (y + 0.5)

世界 → 屏幕
  screenX = cameraOffsetX + zoom * worldX
  screenY = cameraOffsetY + zoom * worldY

屏幕 → 逻辑格
  worldX = (screenX - cameraOffsetX) / zoom
  worldY = (screenY - cameraOffsetY) / zoom
  tileX  = floor((worldX - 276) / 92)
  tileY  = floor((worldY - 184) / 92)
  只有 0<=tileX<10 且 0<=tileY<8 才可点击交互
~~~

**关键风险：** 当前镜头边界按 920×736 计算；A2 若改成装饰世界舞台，需要按 1472×1104 约束相机，同时保留战术区偏移。小地图白色镜头框也应反映**整个新世界场景**的可见区；否则会再次发生鼠标点击/缩放/拖拽与单位位置不一致。

## 四、环境构图与场景分区

**主构图方向**：左上针叶密林 → 左下友军出发区 → 中央战斗草地 → 右侧溪流与岩岸 → 右上赤旗营寨 → 右下瀑布石崖。

| 区域 | 世界逻辑延展（示意，允许部分与可玩区衔接） | 内容与要求 |
| --- | --- | --- |
| 西北森林 | x=-3..2, y=-2..1 | 高大针叶树、林荫、淡雾、石块；远景密而中心格清晰 |
| 西南友军入口 | x=-3..2, y=3..9 | 林间空地、土坡、断墙；保留我军四人清楚可见 |
| 中央交战区 | x=1..7, y=2..7 | 草地、地衣、石子、高亮网格；不要用密集物体盖住互动格 |
| 东北敌方营寨 | x=8..12, y=-2..1 | 赤旗、木栅栏、瞭望台、帐篷、火把；**主要在棋盘外** |
| 东侧河道/木桥 | x=10..12, y=1..6 | 水体、岩岸、桥面与木结构；仅装饰，不能当作可走的格 |
| 东南石崖和瀑布 | x=10..12, y=6..9 | 断崖、碎岩、流水瀑布；不得遮挡统领所在 (9,7) |
| 下边缘补景 | x=-3..12, y=8..9 | 低密度灌木、林地和石坡，遮蔽棋盘矩形边界 |

**构图验收原则**：地图背景尽量完整地占据左侧区域；并非让“10×8 逻辑格”覆盖整个屏幕。逻辑边界外景物必须能显著区分为装饰区域，不能让玩家以为可走到桥上。可用轻微崖边、深林密度和地表断差表达不可通行边界，但不能加新的内部阻挡。

## 五、风格、光照、颜色

- 定位：**原创暗黑奇幻、偏写实手绘、柔和笔触、较高细节密度**，不是纯扁平网格，也不是像素风。保留清晰的棋格操作反馈。
- 摄影机：偏俯视正交视角；树木、岩石和木桥可有 3D 体积感，但角色足点仍与格中心严格对齐。
- 主光照：左上暖色柔光，阴影向右下；水面为冷青蓝反光；火把局部橙暖光。所有素材必须统一此方向。
- 可玩区单位脚下与按钮附近降低纹理对比，防止人物/文字和高亮被背景吞没。
- 蓝友军、红敌军、青蓝移动高亮和暗金 UI 边框属于高优先级阵营色，不要让草地/水色与这些标记发生强烈混淆。

## 六、资源生产清单与尺寸标准

下面是**待生产的资源设计项**，本次没有创建任何真实图片，也没有声明已获得某个素材的授权。

建议在 A2 使用 public/assets/maps/red-banner/ 作为运行时资源根目录，文件名统一英文小写连字符。基础单格 92 CSS px；纹理导出优先按 **2× 即 184px/格** 生产，必要时按高清显示与缩放补充 3×。精灵可用独立透明图或图集合并，严格保证同一光向、俯视角和地面基准点。

| 类别 | 文件名模式 | A2 首批 | A3 扩展目标 | 导出规格参考 |
| --- | --- | ---: | ---: | --- |
| 草地/路面 | ground-grass-*, ground-path-* | 3 | 8 | 184×184 可无缝平铺 |
| 森林簇 | forest-cluster-* | 2 | 7 | 368–736px 透明素材 |
| 松树/矮灌木 | tree-pine-*, bush-* | 0 | 7 | 184–552px，带独立投影 |
| 岩壁与岩石 | cliff-face-*, rock-* | 2 | 8 | 可拼接，透明边缘 |
| 河流与岸线 | river-flow-*, river-bank-* | 2 | 7 | 可拼接水面与岩岸 |
| 木桥 | bridge-wood-* | 1 | 2 | 分离桥面、支架、影子 |
| 营寨 | camp-platform-*, palisade-* | 1 | 6 | 分离营地底座、围栏与瞭望台 |
| 帐篷与赤旗 | camp-tent-*, banner-red-* | 0 | 5 | 透明独立件 |
| 火把/光 | torch-*, fire-glow-* | 0 | 4 | 小素材，动画可关闭 |
| 雾和瀑布 | fog-*, waterfall-* | 1 | 4 | 带透明通道的环境层 |

**A2 最小竖切片：12 项资源**（3 地表 + 2 森林 + 2 石壁 + 2 河道 + 1 桥 + 1 营寨 + 1 雾）。只在具备真实可用资源时才计算“完成件数”；没有素材时可先用明确标注的占位色块验证图层技术。

资源格式：不透明的地表优先 WebP/AVIF；需要透明通道的场景部件优先 WebP Alpha 并保留 PNG 可编辑母版。避免把整张场景和文字 UI 烘焙为大图片。首屏实际下载**预算建议 ≤6 MiB，完整场景资源目标 ≤10 MiB**；属于开发验收预算，尚未测量，不是现有性能指标。

## 七、A2 的分层与命中约束

| 层 | 职责 | 指针事件 |
| --- | --- | --- |
| L0 远景背景 | 视口下方林海/远山兜底，不随可玩格命中 | none |
| L1 地面 | 草地、土径、岩地底纹，随世界镜头移动 | none |
| L2 环境中景 | 岩岸、河流、栅栏、桥、树干 | none |
| L3 战术格 | 10×8 可达区、攻击区、格子命中、格线 | 仅此层接收地图格点击 |
| L4 单位 | 单位徽记/HP、站位、选中框和行动状态 | 经所在逻辑格传递 |
| L5 环境前景 | 树冠、雾、部分前景阴影；不可遮住菜单 | none |
| L6 独立 UI | 设置、右栏、指令菜单、小地图、回合横幅 | 各自 DOM |

A2 不强制恢复 Phaser：可选 DOM 精灵层或 Canvas/WebGL 纯美术层，但应保留文字 DOM 与现有 Battle 的规则真值。
