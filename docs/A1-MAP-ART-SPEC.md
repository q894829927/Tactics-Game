> **状态：A1 设计参数已确定（2026-10-13）；素材生产与 A2 地图重构尚未开始。**
>
> 视觉目标：用户确认的暗黑奇幻战棋概念图，密林、草地、石壁、河流、木桥、瀑布和赤旗营寨。必须生产可分层复用的原创素材，**不能将含有 UI、人物、旗帜和行动提示的概念图整张塞进背景**。

## 1. A1 冻结边界：战术层与视觉层分离

- **战斗逻辑保持现状**：`MAP_WIDTH=10`、`MAP_HEIGHT=8`，平地 `.`、森林 `F`、丘陵 `H`、峭壁 `#`，4 名我方 + 6 名敌军；不修改 `src/engine/battle.ts` 的地形、出生点、寻路、伤害与回合规则。
- **美术舞台比战术地图大**：10×8 之外均为不可交互环境。河流、木桥、瀑布、大片悬崖和营寨构图主要置于战术区外；它们不是新增可走格。
- **不使用菱形等距格**。采用高角度、俯视的 2.5D 手绘风格；画面可有树冠体积、岩壁高差、深度投影，但格子的逻辑投影仍是**正交矩形方格**，不能倾斜战术格中心。
- **美术与命中严格分离**：世界背景、景物、雾、粒子不接收鼠标点击；只允许 10×8 战术命中层发送 `Battle.click(x,y)`。角色名称/数值/菜单等保持可访问的 DOM 文本。

## 2. 精确坐标规范（A2 必须照此实现）

| 参数 | 冻结值 | 说明 |
| --- | --- | --- |
| 逻辑地图 | 10 列 × 8 行 | x 从左向右 0..9，y 从上向下 0..7 |
| 单格世界尺寸 | 92 × 92 世界单位 | 1 世界单位 = 默认缩放 100% 下 1 CSS px；不等于源图片素 |
| 战术内容尺寸 | 920 × 736 单位 | 原引擎当前尺寸，保持不变 |
| 装饰边缘 | 左右各 3 格；上下各 2 格 | 等效逻辑格 x=-3..12, y=-2..9；外围不可通行 |
| **完整世界舞台** | **1472 × 1104 单位** | 16 × 12 等效格；世界原点为左上角 (0,0) |
| **战术原点** | **(276,184)** | 3×92 与 2×92；战术区域占 `[276,1196)×[184,920)` |
| 单位标记锚点 | 格中心 | `(0.5,0.5)` 的格内位置 |
| 竖立景物锚点 | 底部落地处 | 通常使用图片归一化 `anchor=(0.5,1.0)`；投影单独绘制 |
| 全局小地图内容 | 完整 1472×1104 场景 | 包括装饰区，但可走区域需有可辨别边缘 |
| 镜头缩放 | 0.60–1.85 | 沿用当前交互；不会因为素材导出分辨率而改变世界坐标 |

**世界坐标与格子转换（世界坐标是舞台内的坐标，不直接是浏览器坐标）**：

```text
tileTopLeft(x,y) = (276 + 92*x,       184 + 92*y)
tileCenter(x,y)  = (276 + 92*(x+.5),  184 + 92*(y+.5))
screen(wx,wy)    = (cameraX + z*wx,   cameraY + z*wy)

click -> world:
  wx = (pointerLocalX - cameraX)/z
  wy = (pointerLocalY - cameraY)/z
  tileX = floor((wx - 276)/92)
  tileY = floor((wy - 184)/92)
  require 0<=tileX<10 && 0<=tileY<8
  require a real hit-cell in the active tactical layer
```

| 岚锋（我方剑士） | (1,5) | (414,690) |
| 槿卫（我方枪卫） | (1,6) | (414,782) |
| 霜羽（我方弓手） | (2,6) | (506,782) |

**相机实施注意**：当前 `BoardView.ts` 的根世界仅 920×736，没有战术原点偏移；A2 必须显式拆成 `worldStage(1472×1104)` 与 `tacticalLayer(920×736, offset=276,184)`。单格按钮只在战术层内部生成，传给 `Battle.click` 的仍是原始 0..9/0..7。相机边界由整个 1472×1104 舞台计算，不能再用 920×736 的长宽夹取偏移量。缩放以鼠标位置为中心，浮动菜单以投影后的单位世界脚点定位。

**画面填充约束**：在 1920×1080、1366×768 等尺寸，默认镜头尽量让场景充满战场视口；但允许缩放到 60%，此时 1472×1104 场景会缩小到 883×662 视口像素，**在大屏上必然会露出外围**。因此另设不交互的视口级森林远景/云雾外延（见 L0），视觉连续，不再使用明显的环形渐变背景；该外延不扩展可走世界和小地图范围。不能用“强制地图居中”覆盖玩家拖拽。

采用**左侧森林 / 左下友军入口 / 中央可读战术区 / 右上赤旗营寨 / 右侧河谷石桥 / 右下瀑布崖壁**。所有范围使用“相对战术区的等效格坐标”而非像素；重叠范围只表示背景视觉延续，不改变格属性。

| 场景分区 | 建议范围（相对格） | 场景构成与边界规则 |
| --- | --- | --- |
| 西北密林 | x=-3..2，y=-2..2 | 深浅针叶树冠、石块、薄雾；可玩格树木形态须与 `F` 一致 |
| 西南入口 | x=-3..3，y=3..9 | 断墙、坡石、林间空地；不能遮挡四名我军 |

| 东北赤旗营寨 | x=8..12，y=-2..1 | 赤旗、帐篷、木栅栏、瞭望台、火光；主体在棋盘上方/右侧装饰格 |
| 东侧河谷石桥 | x=10..12，y=1..6 | 河流、水雾、岩岸、木桥；**只位于非战术格外侧** |
| 东南断崖瀑布 | x=10..12，y=6..9 | 石壁、瀑布、河道延续；不能遮挡 (9,7) 统领 |

**视线优先权**：玩家选中的单位/当前移动范围 > 战术格状态 > 场景装饰。营寨和桥可在画面有鲜明视觉焦点，但不能挡住 (7,1) 的敌人或 (9,7) 的统领。树冠在战术格附近不做大面积不透明遮挡，必要时按选中范围降低不透明度。

## 5. 艺术规范（冻结色板与质感基准）

- 风格：原创暗黑奇幻、半写实手绘、高角度俯视正交、富有树冠/崖壁体积；**不是 45° 菱形等距、纯像素风或抽象纯色地图**。
- 主光方向：**画面左上 → 右下投影**；傍晚微暖柔光；河面青蓝冷光与营地火把橙色局部光源作对比。
- 地图内容比 UI 低一层对比度：地表避免过高饱和的蓝色/红色，保证青蓝我方、赤红敌军、浅蓝可移动格、白色选中线的辨识度。
- 可玩区背景纹理颗粒相对低于远景；禁用“渐变圆环”大面积填充剩余视口。

### 资源来源与命名约束

资产登记字段：`asset_id,filename,layer,scene_zone,size_px,anchor_xy,alpha,source_type,license,source_url,status`。

- 状态仅可为 `planned`、`in_review`、`approved`、`integrated`；没有真实素材和来源证据时绝不能填 `approved`。
- 素材优先原创绘制/AI 辅助生产并人工调整；使用第三方素材必须核实许可证的修改、分发、署名条件，保留作者与来源。不要照搬受版权保护游戏的具体地形或 UI 素材。
- 即使只作个人学习，公开的 GitHub 仓库也可能构成再分发；“免费可下载”不意味着“可以公开分发”。

## 7. 图层规范（A2 不可擅自换逻辑）

**重要：场景坐标层和屏幕 UI 层是两套坐标系。** 下述逻辑顺序由下至上：

| 顺序 | 层名称 | 内容 | 相机变换 | 鼠标输入 |
| --- | --- | --- | --- | --- |
| S0 | `viewport-backdrop` | 固定视口的远景林海/云雾延展，负责 60% 缩小时的视觉填充 | 独立视口空间或轻视差 | 无 |
| W10 | `world-ground` | 16×12 世界中的草地、土路、地表底纹 | 世界相机 | 无 |
| W20 | `world-environment` | 河水、河岸、岩崖、桥、营地基座、局部阴影 | 世界相机 | 无 |
| W30 | `world-decal` | 地衣、草纹、道具装饰、植被阴影等静态细节 | 世界相机 | 无 |
| W40 | `tactical-hit-grid` | 仅 10×8 格的点击区与格线（偏移 276,184） | 世界相机 | **只有本层接收战术点击** |
| W45 | `tactical-highlight` | 可达/攻击范围、选中格、路线/威胁叠层 | 世界相机 | 无 |
| W50 | `world-units` | 我敌单位徽记、标记阴影、脚点与血条图形 | 世界相机 | 本层标记不拦截格输入 |
| W60 | `world-foreground` | 前景树冠、薄雾、桥栏杆、有限遮挡效果 | 世界相机 | 无 |
| S70 | `screen-unit-labels` | 单位姓名、数值、可读的标记文字、浮动行动菜单 | 屏幕坐标（从世界脚点投影） | 菜单接收点击；其余不拦截 |
| S80 | `screen-HUD` | 设置、小地图、右侧状态栏、回合横幅、版本号 | 不随镜头变换 | 按钮/控件接收 |

**图层实施约束：**

1. 所有 W 层必须共享同一 `cameraX/cameraY/zoom`；W 层不得各自单独计算缩放或贴到另一个 DOM 坐标原点。移动/缩放时世界背景、单位脚点与格子高亮应完全重合。
2. 单位图案和场景容许用 Canvas 2D/WebGL 或 DOM 精灵，但姓名、数值、单位菜单保留屏幕空间 DOM 以避免被缩放变模糊；**不得用整张概念图作 Canvas 底图**。
3. 角色有明确地面脚点。树/建筑按脚点 Y 值决定世界遮挡次序；选中的单位或格子被树冠遮挡时可以动态淡化树冠，但不修改真实通行。
4. 除 W40 与 S70/S80 的明确控件外，所有景物层 `pointer-events:none`；图层透明区域不能挡地图拖拽。鼠标按下/拖拽/点击要区分，距离阈值统一由地图交互层管理。
5. A2 增加世界偏移后，小地图的地图纹理和相机框应对应**16×12 的完整场景**；当舞台完整落在视口内时，镜头白框显示整个舞台，而不是越界负坐标矩形。
6. 选中菜单锚在 `tileCenter` 投影后附近，并对视口做溢出翻转；不允许菜单在世界层内被相机整体缩小。

建议 DOM 容器层级（仅架构示意，不是本次已写代码）：

```text
battlefield viewport
 ├─ S0 viewport-backdrop                (screen / decorative)
 ├─ world-stage 1472×1104               (camera transform)
 │   ├─ W10 world-ground                (decorative)
 │   ├─ W20 world-environment           (decorative)
 │   ├─ W30 world-decal                 (decorative)
 │   ├─ W40 tactical-hit-grid           (10×8, x=276, y=184)
 │   ├─ W45 tactical-highlight          (10×8)
 │   ├─ W50 world-units                 (anchored to tile centers)
 │   └─ W60 world-foreground            (decorative)
 ├─ S70 unit-labels / contextual menu   (screen-space)
 └─ S80 HUD                             (screen-space)
     ├─ gear / minimap / phase banner
     └─ sidebar                          (sibling to battlefield in layout)
```

## 8. A2 竖切片与验收门槛

**先做一小片，再铺满地图**。A2 顺序建议：

1. **A2-1 坐标骨架**：独立的 `world-stage` 和 `tactical-hit-grid`，输入仍精确映射到 `Battle.click`，世界相机与外围装饰区有效；占位色块即可。
