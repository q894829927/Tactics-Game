# v0.1.5.1 地图素材加载优化

> 当前 v0.1.5.2 为改善地形辨识度，用 88,564 字节的天然岩团替换原 175,688 字节横向岩壁，并加入 63,758 字节水面材质。地表和树木 URL 不变；当前四张合计 874,588 字节（约 0.87 MB），继续受 1 MiB 预算约束。共享缓存与异步解码策略保持有效。下面保留 v0.1.5.1 的优化和测量记录。

v0.1.5.0 直接加载了 9,016,975 字节的三张原始 PNG。诊断时，HTML 开始响应约 0.16 秒，而三张 PNG 并行下载分别耗时约 12.3、10.3、10.4 秒，传输大图是主要瓶颈。

## 文件与画质

原始 PNG 保留在美术样张目录。`scripts/optimize-map-art.py` 使用 Pillow/LANCZOS 调整尺寸，导出质量 88 的 WebP，并检查图像可解码、尺寸正确、透明度范围为 0–255，树木/岩壁 Alpha 与缩放后的源图完全一致。精灵世界尺寸、位置、光照、地形和战斗规则均不变。

运行时资源名包含 WebP 内容 SHA-256 前 12 位；资源注册表和 JSON 清单由同一脚本生成，图片内容变化会得到新 URL。测试强制核心素材总量不超过 1 MiB，并核对实际字节、内容哈希、透明数据及原图来源。

## 缓存和解码

`src/scene/mapAssets.ts` 将同一文件的加载合并为一个 Promise、Fetch 响应及 Blob URL，所有主地图/小地图精灵复用。请求使用 `cache: "force-cache"`，以不可变内容哈希路径复用浏览器响应缓存。地表请求提前开始，图片使用异步解码，地表等待解码后绘制。Fetch 异常时改用普通图片 URL，已有失败回退继续有效。

这项优化不依赖 HTTPS Service Worker，也不要求调整服务器 Nginx。当前服务器缓存响应头保持原样；客户端缓存可被浏览器清理或受隐私模式影响，清空缓存后仍会下载约 0.90 MB。不能将文件体积下降比例直接宣称为所有网络环境下的加载耗时下降比例，发布后应重新实测。

## 浏览器验证

内置浏览器验证了 94 个景物全部载入、地表解码后绘制和 185% 缩放清晰度。重新加载页面后，CDP 网络记录显示三张 WebP 均为 `fromDiskCache: true`，每张 `encodedDataLength: 0`，没有重新传输图片正文。主地图与小地图的树/岩壁合计使用两条共享 Blob URL。截图与缓存记录见 `art/map-performance/v0.1.5.1/`；本地缓存结果不用于替代线上冷加载测量。
