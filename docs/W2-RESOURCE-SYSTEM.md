# W2 — 武器耐久与攻击魔法次数（v0.1.23.0）

> 交付范围：**武器实例耐久、破损惩罚、攻击型黑白魔法次数、原子结算、资源UI和可供后续战技系统使用的最小战技接口**。当前普通第一关仍采用现有 4v6 阵容；不引入完整职业/战技菜单或金币经济。

## 一、确定规则

| 场景 | W2实现 |
|---|---|
| 物理普通攻击/反击/通用追击 | **不消耗耐久** |
| 物理战技 | **正式提交时消耗对应实例耐久**；不足禁止。W2提供仅供代码验证的 `w2-power-strike`（伤害+2、耗耐久3），**不在玩家菜单开放**；完整战技在S1 |
| 战技使用恰好耗尽耐久 | 本次已承诺的攻击/追击按**使用前**武器威力结算，结算完成后降为0；后续交战使用破损惩罚 |
| 破损物理武器 | 耐久0时仍能普通攻击、反击、追击；武器威力**-3**（最低0），武器命中**-20**（最低0），无法发动耗耐久战技 |
| 黑/白攻击魔法 | 每个法术ID分别记录本关使用次数；**每次实际发起攻击或合法反击消耗1次，即使命中失败** |
| 魔法追击 | 仍按W0攻速差≥4，只对该次交战扣**一次**法术次数；剩余次数1时也允许合法追击 |
| 魔法耗尽 | 剩余0不能用该法术发起攻击/反击/追击；相关可攻击范围、预测也不可用 |
| 预览、换装、撤销试移动 | 不消耗次数或耐久、不生成战斗日志、不消耗随机数 |
| 恢复资源 | `refillSpells` 仅提供未来**战前整备**用的明确接口，不随结束回合自动恢复；`repairWeapon`仅提供单件维修数据接口，**金币扣除与铁匠铺待E1** |

## 二、初始数值

- 物理武器：常规铁制与其他基础类耐久24、钢制20、练习拳套22。所有武器已写入定义`maxDurability`；这些参数之后可随正式经济平衡微调。
- 攻击魔法：火焰术8、雷电术6、风刃术8、光矢术5次。它们的定义只有`maxCharges`，没有耐久；物理武器则恰好相反。
- 主战斗数据仍保持原有武器威力、重量、命中、射程和库存顺序。

## 三、架构与重要实现边界

`src/engine/combatResources.ts`：
- `WeaponInstance(instanceId,weaponId,durability,maxDurability)`：每件装备一份独立可变实例；即使角色携带两件同名武器，它们也不能共享耐久。
- `SpellCharges`：按法术ID保存独立计数。当前单位的`spellCharges`、`weaponInstances`只在战斗单位上存储，未来关卡与存档可搬入持久角色状态。
- `resourceWeapon`：只生成**本次计算**的有效武器属性，不修改`WEAPON_LIBRARY`或永久定义。即使破损，原武器ID、类型、射程、固有效果也不丢失。
- `consumeArtDurability`、`consumeSpellCast`：仅由已合法提交的行为调用；提供`weaponResourceText`统一菜单与状态栏资源展示。

`src/engine/battle.ts`：
- `combatStats`与`damage`使用相同破损属性，预览与实战共享判定，不仅UI上标注“已损坏”。
- `inAttackRange`与威胁预览根据当前魔法剩余次数屏蔽耗尽法术；攻击方和防守方均执行相同的资源资格判定。
- `strike`记录参与本场交战的施法者，只对同一单位扣**一次**法术次数；若首击击败目标，原本没有出手的防守方不会被扣次数。
- W2样例战技`useCombatArt(actor,defender,"w2-power-strike")`复用普通攻击的移动/权限/预测/命中/反击/追击与提交路径。战技耐久在本次交战事件处理后扣除一次，预览和取消不消耗。此次样例用于验收接口，**没有开放战技菜单、等级解锁、特技装备、技能视觉表现**。
- `Unit.inventory`保留旧WeaponId数组，`Unit.weaponInstances`按索引并行存储，`Unit.spellCharges`独立存储；旧UI、装备测试与第一关均可延续，W2不是完整背包重构。

## 四、验收要点

- 现有全部18件武器类型与资源元数据互斥；物理拥有最大耐久、魔法拥有最大次数。
- 两件同名装备的耐久互不影响，重开战斗恢复初始状态。
- 物理首击、反击、追击不消耗耐久；魔法反击与追击同一次交战扣一次次数。
- 战技命中与未命中均扣耐久，动作取消、预览、非法战技不扣耐久；恰好耗尽时本次攻击按未破损前数值，下一次起降威/降命中。
- 耐久归零后仍能普攻/反击/追击，不可战技；魔法0次后不可继续发动法术攻击/反击/追击。
- 多法术换装不会转移或清空各自剩余次数；`refillSpells`只有明确调用时生效。
- 实际W0追击阈值≥4、W1剑追击×1.2、枪/弓特效、斧最低伤害、拳套回避继续正常。
- 自动测试、TS编译/构建、桌面+手机浏览器、CI以及GitHub `site`发布须通过；ECS的实际版本需单独查验。

## 五、明确未实装

**W2不等于S1、E1或P1。** 以下功能仍待开发：完整战技列表与战技菜单、白魔法治疗/净化、耗两次法术的主动技能、铁匠铺金币支付、自动存档/跨关卡资源结转、E–S+熟练度校验、自由转职与职业精通。本轮只为其提供稳定的资源层。
